## Implemented boundary

The browser sends its Supabase access token in `x-void-user-token`, separate from deployment Basic auth. Next.js verifies that token with Supabase Auth, then uses the service role to read only connections owned by the verified user. Connection APIs apply the same ownership check for every update and delete. The browser roles have no table access to credential records.

The Next.js route encrypts keys with AES-256-GCM and a server-only `ENCRYPTION_KEY`. The application servers share this key; only encrypted records are passed to the internal Express agent. `AsyncLocalStorage` scopes them to a request. The agent filters compatible models before decrypting the selected key. Legacy SQLite shared keys are excluded from this BYOK route.

Auto routing first filters disabled models, required vision/tool support, context capacity and temporary rate-limit cooldowns. It then scores user priority, the selected mode's lightweight task preference, and recent per-user model success/latency EMA. It decrypts one credential at execution time. Rate limits, timeouts and 5xx errors can try another compatible model; authentication and billing failures stop the user-owned route. Manual mode stays on the chosen model.

OpenAI, Groq, Mistral and OpenRouter use the existing OpenAI compatible adapter. Google uses the existing Gemini adapter. Anthropic has a native Messages adapter. Custom providers use the OpenAI compatible adapter with public HTTPS DNS pinning. Model discovery uses provider catalog endpoints and a maintained conservative capability mapper. Users can connect, test, replace, refresh, disable, delete, prefer and select models; routing modes, preferred image model and limited routing events are persisted. General image generation and editing, plus presentation studio's image POST path, use connected OpenAI or Gemini image models. Image requests now contribute provider and model usage events.

## Provider orchestration update

Apply `backend/supabase/migrations/20260924010000_provider_orchestration.sql` after the BYOK migration. It adds per-connection capability switches, preferred voice connection, and a fallback switch. No browser role receives access to ciphertext; the existing service-role-only RLS policy remains in force.

All chat providers use the same agent execution contract and registered tool schemas. Native calls and recoverable text calls pass through the same argument validation and permission checks. Custom APIs without native tool support receive the schemas in a text transport contract and receive tool results through compatible message roles. A rejected native-tools parameter triggers a single compatibility retry. This is separate from an explicit user-disabled tools setting, which is propagated as `toolsEnabled` and cannot be overridden by compatibility transport. Discovery exposes registered schemas for subsequent passes; duplicate successful reads reuse their results and move toward a final answer. Protocol filtering at the agent, Next.js SSE boundary and saved-message renderer prevents transport JSON/XML from appearing as answer code while retaining requested examples and artifact formats.

Next.js validates and encrypts user ElevenLabs keys through the same owned provider connection API as chat and image keys. Voice synthesis routes over the user's connected ElevenLabs accounts, then to managed ElevenLabs for server-authorized admins or when `VOID_ALLOW_FREE_VOICE=true`. Language detection is automatic with no selector. Hindi/Hinglish and supported languages use the low-latency Flash v2.5 model; broader regional speech uses Eleven v3 with voice language metadata. English-only Deepgram is considered only for English. Browser fallback requires a matching language voice. Automatic transcription uses multilingual Whisper when configured, otherwise Nova-3 routes by the inferred conversation language. The client queues short phrases as text arrives and prefetches one ahead; the TTS route streams audio bytes directly, with progressive MP3 playback where the browser supports it. Voice metadata is warmed during listening and cached per credential hash. Image generation tries compatible connected models, then uses the configured Cloudflare image generator only for admins when fallback is enabled. Admins can use it without a connected image key; no additional user key is needed. The optional Pollinations backup remains admin-only and opt-in through `VOID_ALLOW_FREE_IMAGE=true`. Free accounts without an image-capable connection receive a missing-key message. Admin backup images include a notice recommending a preferred image key. Chat and agent turns route through the backend's capability/health-aware BYOK chain, with a managed Groq model for admins. Ordinary accounts without a connected chat model receive a missing-key message; the legacy `VOID_ALLOW_FREE_CHAT` flag no longer grants managed chat. Managed credentials remain server-side and are sent to the backend only as AES-GCM ciphertext over the internal connection.

Admin access is granted through Supabase Auth `app_metadata.role=admin`, the server-only `VOID_ADMIN_USER_IDS` allowlist, or the existing administrator account's confirmed Supabase Auth email. Client-provided email/plan labels have no authority over managed provider access. Set the opt-in free flags only for resources the deployment intends to share. Set the same `ENCRYPTION_KEY` on both application servers, and keep `SUPABASE_SERVICE_ROLE_KEY`, provider keys, and `VOID_INTERNAL_KEY` server-only.

- The web voice LLM turn uses the BYOK chat route; Deepgram STT and TTS remain separate. The optional desktop agent and the legacy presentation image GET URL still use server-key logic.
- Usage events track requests, fallbacks and latency. The web chat records explicitly estimated token counts; the normalized non-stream generation endpoint records provider usage when supplied. Cost estimates are not yet calculated.
- Model capability mapping, metadata refresh scheduling and custom protocol compatibility require further coverage. Poster layout and scoped artifact text editing use the BYOK generation API when configured.


## Explicit workflows and routing (2026-09-28)

Settings now separates provider credentials, orchestration roles and the fallback sequence. Voice controls collapse below provider connections; image provider and model selection follows them. General settings no longer exposes model selectors.

`/api/ai/execution` stores the versioned `void_execution_v1` object in Supabase Auth user metadata. This addition needs no database migration. Every read reconciles assignments against the authenticated user's enabled, connected chat models; every write validates ownership, model eligibility, bounded role instructions and distinct fallbacks. The shared contract orders specialist roles before the final answer writer. Equal-priority defaults are ordered by model ID consistently in settings and chat.

A connected primary model handles the default workflow with no automatically assigned fallback. Explicit specialist roles execute sequentially and feed their reports to the assigned answer writer (or the primary). Multiple roles and fallback models may share one connection. The backend restricts routing to the assigned model and the user's ordered fallback list, retaining capability, context and cooldown checks. Explicit voice and workspace model overrides retain their own routing policy.

Provider/model switches update immediately and serialize writes per resource. Preference updates also serialize and reconcile against the last confirmed save. Workflow drafts survive navigation between settings tabs, saving locks the editor, failed saves retain the draft, and unavailable assignments must be replaced or removed. Motion respects reduced-motion preferences in the workflow editor. `/dev-settings-preview` uses in-memory sample connections and delayed saves for browser checks; its production page returns not found.
